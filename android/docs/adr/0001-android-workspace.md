# ADR-0001 — Android workspace layout and target architecture

- **Status**: Accepted (Phase 0, final review pass)
- **Date**: Phase 0
- **Deciders**: RememberMe maintainers / Phase 0 implementer

## Context

RememberMe is a single self-hosted web app: Astro 7 SSR (`@astrojs/node`
standalone) + React islands, Hono API, Better Auth, Drizzle/libSQL + SQLite,
WebCrypto AES-256-GCM, weekly-digest job via Nodemailer. Baseline (Phase 0,
Bun 1.4.0): 55 tests green; lint, typecheck, and build all pass; git clean
(no tracked/staged changes; pre-existing untracked `spec.md` preserved).

We are adding an **offline, static Android app** without disturbing the
existing Astro/SSR web app. The Android app runs fully on-device (no network
dependency) and reuses as much of the existing domain model, encryption
design, Zod schemas, and UI as practical — with the reuse boundaries and
classifications defined in `porting-plan.md` §4 and `reuse-matrix.md` (the two
documents agree on every item).

Central question: **where does the Android app live in the repository, and
what architecture does it use?**

## Decision

Create a top-level `android/` directory as a **self-contained Capacitor
workspace**, holding:

- `android/package.json` — its own manifest (Vite + React + TypeScript +
  Capacitor 8.x); dependencies tracked in the canonical root `bun.lock`
  (workspace member since Phase 1, see ADR-0002).
- `android/src/` — React application source (adapted from the web client).
- `android/vite.config.ts`, `android/vitest.config.ts`, `android/index.html`,
  `android/tsconfig.json`,
  `android/capacitor.config.ts`.
- `android/android/` — the **native Android project**, **first-class
  repository source**: included and commit-ready, never ignored, and
  **must be tracked when changes are committed** (tracking policy
  below). It is currently untracked, as part of the working-tree
  implementation patch.
- `android/docs/` — porting plan, reuse matrix, ADRs.

Architecture of the Android target:

- **Static + offline-first**: plain Vite build copied into the Capacitor
  native shell. No SSR, no `@astrojs/node`, no Hono, no Better Auth, no
  Nodemailer, no SMTP digest — web-only and untouched.
- **Storage**: on-device **SQLite (Phase 3)**; JS storage (localStorage /
  IndexedDB) is not an allowed substitute.
- **Crypto**: only the crypto library/plugin **selection** is deferred to the
  Phase 4 technical spike; on-device secure-key management + optional
  biometric / device-credential unlock (Phase 8) are committed.
- **Product parity**: local weekly notifications + in-app Weekly Review
  (Phase 6), encrypted `.rmbak` backup/restore + legacy migration (Phase 7),
  optional biometric / device-credential unlock (Phase 8) — committed scope.
- **Shared module (Phase 2)**: a dependency-free shared module for Zod
  journal schema, lower-level timezone primitives, and the extracted pure
  calendar/week/content model (see Consequences — the weekly *server module*
  itself is not shareable). `shared/schemas/settings.ts` is **not** shared
  verbatim; Android defines its **own settings schema** on top of the timezone
  primitives.

### Native source (first-class) vs ignored artifacts

Native **source** (first-class; commit-ready and **must be tracked when
changes are committed**): `android/android/app/src/**`
(manifest, `MainActivity`, `res/`), `android/android/*.gradle`,
`settings.gradle`, `gradle.properties`, the `gradle/` wrapper
(`gradlew`, `gradle/wrapper/**`), `capacitor.config.ts`, `android/package.json`.
(Since Phase 1 the Android dependencies are captured in the canonical root
`bun.lock`, not a per-package lockfile — ADR-0002 supersedes the original
"own Bun lockfile" arrangement.) Rationale: the Android manifest, resources,
native plugin hooks, and the CI build/APK pipeline are first-class source —
reproducible builds, auditable manifest/resources, tracked plugin
integration. The manifest sets `android:allowBackup="false"`, disabling
automatic OS/ADB app backup so backup/restore stays exclusively under the
product's explicit encrypted `.rmbak` flow (Phase 7) and its in-app/device
local export — consistent with the on-device Keystore threat model
(ADR-0002 records the full rationale).

Ignored / generated artifacts (never committed): `android/android/.gradle/`,
`android/android/build/`, `android/android/app/build/`,
`android/android/local.properties` (machine SDK path), signing secrets
(`*.keystore`, `*.jks`, `keystore.properties`, signing env),
`android/node_modules/`, `android/android/capacitor-cordova-android-plugins/`
(regenerated by `cap sync`), logs. **These patterns are enforced in the root
`.gitignore` as of Phase 0** (precise Android patterns; the included
`android/android` native source is never ignored). See `porting-plan.md`
§3a.

### Toolchain / package management

No competing package-manager or build-orchestrator stack: the repo continues
to use **Bun** (pin `bun@1.3.14`) for the web app and the `android/`
workspace; **no pnpm, yarn, Nx, or Turbo**. `android/package.json` uses
`bun run` scripts; since Phase 1 (ADR-0002) the root `bun.lock` is the
single canonical lockfile for both workspaces.

Root commands (`bun run lint` / `typecheck` / `test` / `build`) are the
**Astro web workspace's** commands and do **not** cover Android. Android has
its own scoped scripts in `android/package.json` (lint, typecheck, test,
Vite build, `cap sync`, `cap add android`) plus native/Gradle gates
(`assembleDebug` / `assembleRelease`) — see `porting-plan.md` §3b. Root CI
(`.github/workflows/ci.yml`) stays web-only; an Android CI job is added in
Phase 9 (extend the existing workflows, never rewrite them — inventory in
`porting-plan.md` §2f).

## Rationale

1. **Isolation without fork**: a top-level `android/` keeps both targets in
   one repo (single history, shared-module potential) while keeping the
   Capacitor/Vite/Node toolchain fully separate from the Astro workspace —
   different `package.json`, `tsconfig`, build output (dependencies share
   one root lockfile since Phase 1, ADR-0002).
2. **Minimal blast radius**: the Astro app's `package.json`, scripts, and
   lockfile stay as-is; no Capacitor dependency leaks into the SSR bundle.
3. **Static/offline matches the product**: single-owner, private, no
   phone-home — the natural Android expression of the web app's privacy
   stance.
4. **Reuse with clear boundaries**: pure logic and UI primitives are highly
   reusable; server/HTTP/DB code is cleanly excluded (`reuse-matrix.md`).
5. **Capacitor 8 is the current stable major** and the compatible direction
   (v9 alpha at `/docs/next/`); core/cli/android and all official plugins pin
   to 8.x, with `cap sync` required after dependency changes.

## Consequences

### Positive

- Web app untouched; zero regression risk to the 55-test suite.
- Additive workspace; independent web and Android CI.
- Shared schema/timezone/week model reuse limits cross-target drift.
- Native project kept as first-class source (never ignored) makes builds
  reproducible and audits manifest / resources / plugin integration in
  review.

### Negative / costs

- Two build pipelines (Astro + Vite) over partially shared source.
- Cross-target sharing requires the Phase 2 extract decision (package vs
  copy+sync test) because the toolchains share no module graph.
- Android adds a native toolchain requirement (Node ≥22, Android Studio
  ≥2025.2.1, API 36 latest); the Phase 0 machine has none (see Risks).

### Risks

- **Crypto/format coupling**: whether the on-device cipher can *read* the web
  DB's `{encryptedContent, iv, authTag}` layout is gated behind the Phase 4
  crypto spike; Android reads that layout only for legacy migration (Phase 7),
  never persists it. Import is transactional with explicit
  wrong/missing/corrupt-key handling and rollback.
- **On-device key management**: no env on Android; key lifecycle resolved in
  Phase 4 (secure storage) + Phase 8 (biometric / device-credential unlock).
  Key loss = data loss, mitigated by `.rmbak` backup (Phase 7).
- **Shared-module purity**: shared files must stay dependency-free
  (zod/luxon); the extracted calendar/week model must fix the web's UTC-zoned
  timezone handling before it is shared (see `porting-plan.md` §8).
- **Toolchain unavailable locally (confirmed)**: no Java runtime
  (`/usr/bin/java` stub; `java -version` fails), `ANDROID_HOME` /
  `ANDROID_SDK_ROOT` unset, no `sdkmanager`, no Android SDK dirs — provision
  before any native build (Phases 1/9).

## Alternatives considered

- **Monorepo workspaces (pnpm/npm/yarn) at the root** — merges toolchains
  into one lockfile/install, higher blast radius on the web app; also
  contradicts the Bun-only decision. Rejected.
- **Fork a separate repository** — cleanest isolation but loses single-source
  sharing and shared history; rejected because reuse is a stated goal.
- **Reuse the web DB server from Android** — contradicts offline-first /
  no-phone-home. Rejected.
