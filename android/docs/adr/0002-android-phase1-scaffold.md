# ADR-0002 — Android Phase 1 scaffold: versions, scripts, workspace integration

- **Status**: Accepted (Phase 1, implementation complete)
- **Date**: Phase 1
- **Deciders**: RememberMe maintainers / Phase 1 implementer

## Context

Phase 0 (ADR-0001) established the repository layout: a top-level `android/`
Capacitor workspace hosting a Vite + React + TypeScript app with the generated
native project nested at `android/android/`, included as **first-class
source** (commit-ready, never ignored, and tracked when the work is
committed). Phase 1
scaffolds that workspace: a runnable mobile shell, the actual native project,
scoped scripts, workspace-level dependency capture, and green lint/typecheck/
test/build/sync gates.

This ADR records the **actual** Phase 1 outcome: dependency versions as
resolved and verified, the application ID, the final script surface, the
workspace integration decision, gate results, and the native-toolchain
limitation.

## Decision

### Application ID

`app.rememberme.journal` — derived directly from the product identity
(RememberMe + journal domain); matches the top-level `android/` directory
name in reverse-DNS form (`app.rememberme.journal`). Set in
`android/capacitor.config.ts` (`appId`) and stamped into the generated native
project: `applicationId` and `namespace` in
`android/android/app/build.gradle`, Java package
`app/rememberme/journal/MainActivity.java` (package `app.rememberme.journal`).
No third-party reverse-domain ownership implication; kept stable across
phases (changing it later would orphan installed app data).

### Vite-8 alignment fix (Mechanical Phase 1)

`android/package.json` moved `vite` ^7 → **^8.2.2**, `@vitejs/plugin-react` ^4.7 → **^5.2.0**, `vitest` ^3 → **^4.1.11** (compatible stable majors; the web app already resolved to `vite 8.2.1` via astro `^8.0.13`, so android's Vite 7 forced nested duplicates in the root lockfile). After a fresh root `bun install` (lockfile regenerated, single hoisted `vite@8.2.2`, zero `vite@7`), the dedupe also pulled several direct/transitive deps to latest-in-range, and root `bun install --frozen-lockfile` verified clean (601 installs / 779 packages, no changes). Capacitor stays aligned at **8.5.1** (core/cli/android). `capacitor.config.ts` was added to `android/tsconfig.json` `include` (resolves normally via `@capacitor/cli` types; no package added to `types`). `android/src/test/app.vitest.tsx` table callbacks now carry explicit `(path: string, heading: RegExp)` types (no `any`).

### Root Bun workspace integration

Decision: **minimal root Bun workspace**. `android/` is declared as a
workspace in the root `package.json` (`"workspaces": ["android"]`), so the
**root `bun.lock` is the single canonical lockfile** capturing the Android
dependencies (`@rememberme/android` resolves as `workspace:android`). The
standalone `android/bun.lock` produced by the intermediate singled-package
install was **removed** as a stale duplicate — keeping two lockfiles that can
drift would defeat lockfile-gated installs. Root `bun install
--frozen-lockfile` verifies cleanly against the canonical lockfile (601
installs / 779 packages, no changes). This is the "minimal workspace
integration" called for by the Phase 1 goal: no pnpm/yarn/Nx/Turbo; Bun
remains the single package manager; the web app's lockfile is unchanged in
meaning, only extended with the android workspace block.

### Script surface

Android workspace scripts (`android/package.json`) — invoked as
`bun run --cwd android <script>`:

| Script | Command | Type |
| --- | --- | --- |
| `dev` | `vite` | dev server (local-only, no external URL) |
| `preview` | `vite preview` | preview built `dist/` |
| `build` | `vite build` | web build (alias of build:web, keeps `build` name generic) |
| `build:web` | `vite build` | explicit web build |
| `build:debug` | `bun run build:web && bun run cap:sync && cd android && ./gradlew assembleDebug` | web build → `cap sync` → native debug APK |
| `typecheck` | `tsc --noEmit` | |
| `lint` | `biome check .` | **full scope**: `src/**`, `vite.config.ts`, `vitest.config.ts`, `capacitor.config.ts`, `package.json` per `android/biome.json` `files.includes`; the generated native project `android/android/` is **not** in the include set (excluded, never linted as handwritten) |
| `test` | `vitest run` | 7 shell/router tests |
| `cap:sync` | `cap sync android` | copies `dist/` → native assets, updates plugins |
| `cap:open` | `cap open android` | open native project in Android Studio |
| `android:add` | `cap add android` | (re)generate native scaffold |

Root convenience wrappers (`package.json`) — preserve existing web script
meanings; each is a pure passthrough to the android workspace:

| Script | Command |
| --- | --- |
| `android:dev` | `bun run --cwd android dev` |
| `android:test` | `bun run --cwd android test` |
| `android:build` | `bun run --cwd android build` |
| `android:sync` | `bun run --cwd android cap:sync` |
| `android:open` | `bun run --cwd android cap:open` |

The root web scripts (`dev`, `build`, `start`, `preview`, `typecheck`,
`lint`, `test`, `db:*`) are **unchanged in meaning and text**: the root
`test` script remains exactly `bun test`. It runs the web suite as before
and, since Phase 2 added the `packages/*` workspaces, also discovers the
shared-core tests (`@rememberme/core`). Android stays isolated by filename,
not by scoping the root command: `vitest` is configured with the explicit
include `src/**/*.vitest.{ts,tsx}` in `android/vitest.config.ts`, and
`.vitest.` is not a pattern Bun's test runner discovers — so the Android
suite runs only under `bun run --cwd android test` (vitest), with no
spurious root failures and no root script change.

### Biome for Android

`android/biome.json` is additive and mirrors the web workspace's formatter/
linter settings (tabs, width 100, `recommended` preset with the same two
relaxations as root conventions: `noExplicitAny` off, `noConsole` off,
`noParameterAssign` off). `files.includes` restricts checks to handwritten
source (`src/**`, `vite.config.ts`, `vitest.config.ts`, `capacitor.config.ts`,
`package.json`)
and **excludes generated output** (`dist`, `node_modules`, `*.css`); the
generated native project is excluded by not being listed. Root `lint`
(`biome check src tests scripts`) is untouched — this is a separate config,
not a weakening of the root gate.

### Generated native project

`android/android/` is present as **first-class native source** per
ADR-0001 — included and commit-ready, never ignored, and **must be tracked
when this work is committed**. Like the rest of the `android/` tree it is
currently **untracked**, part of the working-tree implementation:
`app/src/main/AndroidManifest.xml` (no unnecessary permissions — only the
Capacitor-generated `INTERNET` baseline required by the WebView local server
that serves the bundled web assets over the virtual `https://` scheme),
`app/src/main/java/app/rememberme/journal/MainActivity.java`, `res/`,
`*.gradle`, `settings.gradle`, `gradle.properties`, and the `gradle/` wrapper
(`gradlew`, `gradle/wrapper/**`).

#### Automatic OS backup disabled (`allowBackup="false"`)

The manifest sets `android:allowBackup="false"`, disabling Android's
automatic cloud/ADB app backup (Auto Backup on API 23+, plus the legacy
`backup`/`restore` attributes). Backup/restore is handled **exclusively** by
the product's explicit, encrypted `.rmbak` backup/restore flow (Phase 7) and
in-app/device local export — never by an unauthenticated OS background copy.
This matches the on-device Keystore threat model: the SQLite store and key
material live in app-private storage, and a silent OS backup could otherwise
surface a recoverable copy of encrypted state (or worse, a plaintext pull via
ADB) outside the app's control, outside the `.rmbak` encryption/password
contract, and with no per-phase justification. Disabling automatic backup
keeps data lifecycle and key custody under the app's explicit, audited,
password-protected channels only.

Ignore verification (root `.gitignore` + generated `android/android/.gitignore`):
`local.properties`, `.gradle/`, `**/build/`, `capacitor-cordova-android-plugins/`,
`android/node_modules/`, `android/dist/`, `android/coverage/`, keystore/
signing secrets are all ignored (`git check-ignore` confirms); every native
**source** file listed above is **not** ignored.

### Native/Gradle gate — SKIPPED (toolchain unavailable), never claimed as pass

`bun run --cwd android build:debug` (web build → `cap sync` → `./gradlew assembleDebug`)
was **attempted** and fails at the Gradle step with the exact coordinator-
baseline reason:

- No Java runtime: `java -version` /
  `/usr/libexec/java_home` → "Unable to locate a Java Runtime"; `JAVA_HOME`
  unset.
- `ANDROID_HOME` and `ANDROID_SDK_ROOT` unset; `sdkmanager` not found; no
  Android SDK directories.

The `vite build` + `cap sync` **portion** of `build:debug` completes; `./gradlew
assembleDebug` cannot run without a JDK + SDK, so **no Gradle verification
was performed and none is claimed**. Status: **SKIPPED** with the reason
above — identical to the Phase 0 baseline (ADR-0001 Risks). Provision a JDK
(21, required by the native `compileOptions` `VERSION_21` — Capacitor 8's
generated `capacitor.build.gradle`) and Android SDK (API 36) locally or in
CI (Phase 9) before the native build gate can pass.

## Consequences

### Positive

- Root `bun.lock` is a single canonical lockfile covering web + Android;
  lockfile-gated CI installs verify one source of truth.
- All non-native gates green; the workspace integration introduced no web
  regression (55 web tests still pass, build/lint/typecheck unchanged).
- Config files are linted (Biome), closing the "handwritten config unlinted"
  gap while generated output stays excluded from checks.
- Script surface is stable and semantically named; root wrappers are pure
  passthroughs, so web script meanings are preserved.

### Negative / costs

- Native build still cannot be verified on this machine (toolchain
  limitation, see above); `build:debug` is part of the commit-ready
  implementation and correct but red locally until a JDK + SDK exists.

### Risks

- **Lockfile scope**: the workspace integration means Android dependency
  bumps now also touch root `bun.lock`. Future Android dep changes must run
  at the root (`bun install`) and refresh `bun.lock`; `cap sync` still
  required after any plugin change.
- **INTERNET permission**: kept as Capacitor's generated WebView baseline
  (local-asset serving over the virtual https scheme); the app code makes no
  network calls. Any future permission addition must be justified per-phase
  (notifications Phase 6, storage/security Phases 3–8).
- **App ID stability**: `app.rememberme.journal` is fixed and stamped into
  the native project; changing it later orphans installed app data
  (Android treats package rename as a new app).
